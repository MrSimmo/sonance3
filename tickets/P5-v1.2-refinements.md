Visual and interaction refinements based on real TV testing. Covers layout fixes, highlight style overhaul, album art background blur, exit dialogue, and Now Playing screen fixes.

## Tasks

### P5.1 — Library Grid: Vertical Scroll Only (No Horizontal Scroll)
**Problem:** Library → Albums and Artists tabs allow horizontal scrolling. They should wrap to fit the screen width and scroll vertically only.
**Fix:**
- In the Albums tab grid: ensure `grid-template-columns` creates enough columns to fill the available width, items wrap to the next row, and the container scrolls vertically
- Set `overflow-x: hidden; overflow-y: auto` on the grid's scroll container
- Same for Artists tab grid
- Also apply to Home screen horizontal rows (Recently Played, Recently Added, Playlists) — these currently scroll horizontally. Convert them to wrapping grids or keep horizontal but ensure no items are clipped off-screen. **On reflection:** the Home screen rows SHOULD be horizontal (that's the Apple Music convention). Only the Library grid views should wrap vertically. Keep Home rows as horizontal scroll.
- Test: resize browser to 1920×1080, verify no horizontal scrollbar appears on Library tabs

### P5.2 — Back Button Exit Dialogue on Main Screens
**Problem:** Pressing Back on a main screen (Home, Library, Search, etc.) does nothing. It should offer to exit the app.
**Fix:**
- When Back (keyCode 10009 / Escape 27) is pressed and the navigation history stack is empty (i.e. the user is on a top-level screen like Home), show an exit confirmation dialogue
- Dialogue design:
  - Centred modal overlay with dark semi-transparent background (`rgba(0,0,0,0.7)`)
  - Card: `--bg-card` background, `--border` border, border-radius 16px, padding 32px, max-width 400px
  - Text: "Exit Sonance?" (20px, weight 600, `--text-primary`)
  - Subtitle: "Are you sure you want to exit?" (14px, `--text-secondary`)
  - Two buttons side by side:
    - "Cancel" — `--bg-elevated` background, `--text-primary` text, border-radius 10px
    - "Exit" — `--accent` background (or a subtle red like `#ef4444`), white text, border-radius 10px
  - Focus starts on "Cancel" (safe default)
  - Enter on Cancel: dismiss dialogue, return to normal
  - Enter on Exit: call `tizen.application.getCurrentApplication().exit()` (on Tizen) or `window.close()` (browser fallback)
  - Back key while dialogue is open: dismiss dialogue (same as Cancel)
- FocusManager: create an isolated modal zone with 2 items (Cancel, Exit), Left/Right navigation
- Do NOT use `position: fixed` (Tizen issue) — use `position: absolute` on a full-screen overlay div that's a direct child of `#app`

### P5.3 — Album Art Background Blur (Apple Music Style)
**Problem:** The Now Playing screen and other areas look flat. Apple Music uses a blurred version of the album art as the background.
**Fix:**
- **Now Playing screen:** Replace the current radial gradient background with a blurred album art background:
  ```css
  .np-bg-image {
      position: absolute;
      top: -10%; left: -10%;
      width: 120%; height: 120%;  /* overflow to avoid blur edge artifacts */
      background-size: cover;
      background-position: center;
      filter: blur(50px) saturate(1.3);
      z-index: 0;
  }
  .np-bg-overlay {
      position: absolute;
      top: 0; left: 0;
      width: 100%; height: 100%;
      background: rgba(10, 10, 12, 0.55);
      z-index: 1;
  }
  .np-content {
      position: relative;
      z-index: 2;
  }
  ```
- Set the `.np-bg-image` div's `background-image` to the album's cover art URL (full size, e.g. `getCoverArtUrl(coverArt, 600)`)
- When track changes, update the background image
- **NOTE:** `filter: blur()` IS supported on Chromium 63 (Tizen 5.0). It is `backdrop-filter` that is NOT supported. This approach applies blur to a regular element, which is fine.
- Also apply a subtle version to the **sidebar background** when music is playing — a very faint, heavily blurred version of the current album art behind the sidebar (opacity 0.1-0.15, blur 80px). This gives the whole app a cohesive feel. If this is too complex or causes performance issues, skip the sidebar version.
- **Now Playing bar (footer):** Apply a similar but subtler blur behind the now playing bar — or simply use a darker semi-transparent background since the bar is small.

### P5.4 — Highlight Style Overhaul
**Problem:** Pink rectangular boxes around focused items look harsh, especially on Now Playing transport controls and sidebar items.
**Fix — different highlight styles for different contexts:**

**Now Playing transport controls (shuffle, prev, play/pause, next, repeat):**
- Remove the pink outline/border entirely
- When focused: tint the icon/button with `--accent` colour
- For the play/pause circle: keep the white circle but add a subtle pink glow (`box-shadow: 0 0 20px rgba(228, 77, 138, 0.5)`) when focused
- For icon-only buttons (shuffle, prev, next, repeat): change icon colour from `--text-secondary` to `--accent` when focused, add subtle glow
- No transform scale on these — they should stay in place

**Sidebar nav items:**
- Remove the pink outline box entirely
- Remove the lighter coloured right-hand border on the active item
- **Active item (current screen):** full-width pink/accent background fill (`--accent` background), white text, white icon. No border. Border-radius 8px with some horizontal margin (e.g. margin: 0 12px, padding stays the same)
- **Focused item (d-pad highlight, not active):** text becomes `--accent` colour, font-weight becomes 600 (bold). No background, no border. Just the text/icon colour change.
- **Unfocused/inactive:** `--text-secondary` colour, normal weight

**Library grid cards, album cards, playlist cards:**
- Keep the pink outline but make it thinner (1.5px instead of 2px) and reduce outline-offset to 2px
- Keep the `scale(1.04)` transform
- These are card-based elements where the outline works well

**Search keyboard keys:**
- Keep current style (background colour change on focus)

**Queue/tracklist rows:**
- Keep current style (subtle background highlight on focused row)

### P5.5 — Remove Sidebar Active Item Right Border
**Problem:** The active sidebar menu item has a lighter coloured border on the right side.
**Fix:** This is addressed in P5.4 above — the active sidebar item becomes a full pink filled box with no borders. Ensure the `border-right` is removed.

### P5.6 — Album Detail: Fix Truncated Highlight & Reduce Cover Art Size
**Problem:** In Album Detail, the focus highlight box is truncated/clipped, and the cover art is too large.
**Fix:**
- Reduce album art in Album Detail from 300px to 240px
- Reduce the left panel width from 300px to 260px proportionally
- Ensure the focus outline on album cards in the Library grid is not clipped:
  - The grid container or parent may have `overflow: hidden` which clips the outline
  - Add `padding: 6px` to the grid container to give outlines room to render
  - Or change from `outline` to `box-shadow: 0 0 0 2px var(--accent)` which doesn't get clipped by overflow

### P5.7 — Hide Now Playing Bar During Now Playing Screen
**Problem:** The persistent Now Playing bar at the bottom is redundant when viewing the full Now Playing screen.
**Fix:**
- When navigating TO the Now Playing screen: slide the Now Playing bar down and out of view
  - Animation: `transform: translateY(100%)` with `transition: transform 0.3s ease`
- When navigating AWAY from the Now Playing screen: slide the Now Playing bar back up into view
  - Animation: `transform: translateY(0)` with `transition: transform 0.3s ease`
- **IMPORTANT:** Only animate the slide-up when transitioning FROM the Now Playing screen specifically. Do NOT animate on other screen transitions (e.g. Home → Library should not trigger any bar animation)
- Implementation:
  - In the router's `navigateTo()` method, check if we're leaving or entering the Now Playing screen
  - Add/remove a CSS class like `.np-bar-hidden` that applies `transform: translateY(100%)`
  - The transition CSS handles the animation automatically
- When the Now Playing bar is hidden, the content area should expand to fill the space (adjust bottom padding)

### P5.8 — Fix Now Playing Screen: Blue Bar & Gradient Not Filling
**Problem:** On the TV, there's a blue/grey bar on the right side of the Now Playing screen, and the gradient background has black bars on the left, right, and bottom.
**Fix:**
- The Now Playing screen background must fill the ENTIRE content area edge-to-edge, including any scrollbar gutter
- Set the Now Playing screen container to:
  ```css
  position: absolute;
  top: 0; left: 0; right: 0; bottom: 0;
  overflow: hidden;
  ```
  (relative to the `#content-area`)
- Ensure the background blur image div (from P5.3) extends beyond the viewport edges (the `top: -10%; width: 120%` trick handles this)
- The blue bar is likely caused by:
  - A scrollbar gutter (`scrollbar-gutter: stable` or similar)
  - The `#content-area` having a right padding or border
  - The Now Playing screen not having `overflow: hidden`
- Force `overflow: hidden` on the Now Playing screen's root container
- Force `width: 100%; height: 100%` on the Now Playing screen
- Remove any padding from the content area when Now Playing is active (add/remove a class)
- Test: the background should bleed to all edges with no gaps

### P5.9 — Search Screen: Enlarge Keyboard, Narrow Results
**Problem:** On the TV, the on-screen keyboard is too small and the Quick Access/results panel is disproportionately wide.
**Fix:**
- Increase the keyboard panel width from 380px to ~480px
- Increase keyboard key sizes: larger padding, larger font (18px instead of 16px)
- Increase gap between keys slightly
- Results/Quick Access panel: reduce to fill the remaining space (it will naturally shrink as the keyboard grows)
- Quick Access cards: reduce from 3-column to 2-column grid to fit the narrower space
- Search input: increase font size to 18px for TV readability
- SPACE and DEL keys: increase height to match the larger key sizes
- Test at 1920×1080: keyboard should be easily readable at 2-3m viewing distance

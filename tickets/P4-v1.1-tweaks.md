# P4 — Sonance v1.1 UI Tweaks & Improvements

## Overview
A collection of UI refinements, feature adjustments, and usability improvements based on real TV testing. This is a single patch covering 12 items.

## Prerequisites
- Read CLAUDE.md for project rules
- Read docs/UI-MOCKUP-REFERENCE.md for design reference
- Read PROGRESS.md for current state
- All previous patches (P1–P3) applied

## Tasks

### P4.1 — Shrink Album Art in Library Grid
**Problem:** Album covers in the Library → Albums tab are too large. The grid only fits ~6 albums on screen.
**Fix:**
- Reduce album art size by ~25% in the Library albums grid
- Change grid from `grid-template-columns: repeat(6, 1fr)` to `repeat(8, 1fr)` (or 7 if 8 is too cramped at 1080p)
- Reduce gap proportionally
- Ensure the focus ring scales with the smaller cards
- Album title and artist text below can go to 12-13px to fit
- Test that text doesn't overflow — use `text-overflow: ellipsis` as before

### P4.2 — Remove Volume Controls Everywhere
**Problem:** Volume is controlled by the TV remote's hardware volume buttons. In-app volume controls are redundant and confusing.
**Fix:** Remove volume UI from ALL locations:
- **Now Playing screen:** Remove the volume bar at the bottom (speaker icons + progress bar)
- **Now Playing bar (footer):** Remove volume icon and mini progress bar on the right side
- **Settings screen:** Remove the volume bar/percentage display from the Playback section
- **Player engine:** Keep the internal volume state for the HTML5 Audio fallback (browser testing) but do not expose any volume UI
- Do NOT remove the `volume.set` privilege from config.xml — it may be needed for AVPlay

### P4.3 — Enlarge Icon SVG Content
**Problem:** The S-wave design inside the gradient icon box is too small in both the login screen and sidebar logo.
**Fix:**
- In both locations, scale up the inner SVG paths so they fill more of the container
- The S-wave arcs and emanation lines should use roughly 70-80% of the icon area (currently they're using about 50%)
- Increase stroke widths proportionally
- Keep the gradient background box and rounded corners unchanged
- Test at both sizes: login (~80px) and sidebar (36px)

### P4.4 — Remove Top Bar
**Problem:** The top bar showing the page title and user avatar is redundant — the active sidebar item already indicates which page you're on.
**Fix:**
- Remove the entire `#top-bar` element (60px) from the app shell
- Adjust the content area to fill the space: it should now start from the very top of the main section
- Remove the user avatar circle entirely
- Remove any stats text that was in the top bar
- Update the layout CSS: `#content-area` should now have `top: 0` instead of `top: 60px` (or remove the top bar height from the flex layout)
- Verify all screens render correctly without the top bar
- Update FocusManager if any zones referenced the top bar

### P4.5 — Move Shuffle/Repeat from Settings to Now Playing Only
**Problem:** Shuffle and Repeat mode toggles appear in Settings, which is the wrong place. These are playback controls and belong on the Now Playing screen only.
**Fix:**
- Remove the Shuffle/Repeat indicators and toggles from the Settings screen
- Settings → Playback section should only show informational items (or be removed entirely if empty after this change)
- Verify Shuffle and Repeat toggles work correctly on the Now Playing screen:
  - Shuffle icon: press Enter to toggle on/off, icon should highlight in `--accent` when active
  - Repeat icon: press Enter to cycle none → all → one, icon should highlight when active, show "1" badge for repeat-one mode
  - State persists in localStorage across screen changes and app restarts
- **Thorough testing required:**
  - [ ] Enable shuffle → play album → tracks play in random order
  - [ ] Disable shuffle → queue reverts to original order
  - [ ] Enable repeat all → after last track, queue loops to first track
  - [ ] Enable repeat one → current track loops indefinitely
  - [ ] Disable repeat → playback stops after last track
  - [ ] Shuffle + Repeat All combined → shuffled queue loops
  - [ ] Visual indicators update correctly on toggle
  - [ ] State persists after navigating away and back to Now Playing
  - [ ] State persists after page reload
- Log all test results to PROGRESS.md

### P4.6 — Move Connection Status to Settings
**Problem:** The "Connected" indicator and server URL in the sidebar footer is unnecessary clutter in the main app view.
**Fix:**
- Remove the connection status section from the sidebar footer (the green dot, "Connected" text, and IP address)
- The sidebar should end after the last nav item (Settings), with just padding at the bottom
- Add the connection status to the Settings screen instead:
  - In the Server Information section, add a status line: green dot + "Connected" (or red dot + "Disconnected") alongside the server URL
  - Optionally: add a "Test Connection" button in Settings that calls `ping.view` and shows the result

### P4.7 — Queue Management with Colour Buttons
**Problem:** The Queue screen exists but there's no way to add items to it or manage it from other screens.
**Fix:**
- Register Samsung remote colour button keycodes:
  - Red: 403, Green: 404, Yellow: 405, Blue: 406
  - Also handle `KeyboardEvent.key` values: `ColorF0Red`, `ColorF1Green`, `ColorF2Yellow`, `ColorF3Blue`
- On screens where tracks/albums are focusable (Library songs, Album Detail tracklist, Search results, Playlist detail):
  - **Yellow button (405):** Add focused track to end of queue. Show a brief toast notification: "Added to queue"
  - **Blue button (406):** Add focused track as "play next" (insert after current track in queue). Show toast: "Playing next"
  - **Red button (403):** On the Queue screen only — remove focused track from queue. Show toast: "Removed from queue"
- On Album Detail screen when an album card is focused:
  - **Yellow button:** Add all album tracks to end of queue
  - **Blue button:** Add all album tracks as "play next"
- Add a **colour button hint bar** at the bottom of relevant screens (above the Now Playing bar):
  - Thin bar (28-32px) with subtle background
  - Shows available actions: e.g. "Y Add to queue   B Play next" (with colour dots)
  - Only visible on screens where colour buttons are active
  - Does NOT show on Home, Settings, Search keyboard area, or Now Playing
- **Toast notification system:**
  - Small toast (dark background, white text, 12-14px) appears top-right or bottom-centre
  - Auto-dismisses after 2 seconds
  - Animates in/out with opacity transition
- Test on the TV: if colour buttons don't register, document this in PROGRESS.md and note that the feature requires TV testing. The browser fallback keybindings can use keyboard shortcuts (Y, B, R keys) for dev testing.

### P4.8 — Validate 4K / Viewport Configuration
**Problem:** The TV is 4K (3840×2160) but we need to confirm the Tizen WebView renders at 1080p as expected.
**Fix:**
- Verify `index.html` has the correct viewport meta tag:
  ```html
  <meta name="viewport" content="width=1920, initial-scale=1.0">
  ```
  This tells the Tizen WebView to render at 1920px width regardless of the physical resolution. The TV upscales.
- If the viewport is currently set to `width=device-width`, change it to `width=1920` — `device-width` on a 4K TV would give 3840px which would make everything tiny
- Verify all layout assumptions are based on 1920×1080
- No other changes needed — the TV's hardware scaler handles the rest

### P4.9 — Add "Recently Added" to Home Screen
**Problem:** Home screen only shows "Recently Played" (or "Newest Albums"). Users also want to see what's been recently added to the library.
**Fix:**
- Add a new section to the Home screen: **"Recently Added"**
- Fetch via `getAlbumList2('newest', 6)` — this returns albums sorted by date added to library
- Display as a horizontal row of 6 album cards (same format as the existing recently played row)
- Position: below the hero banner, above "Recently Played"
- If "Recently Played" is already using the `newest` type, change it to `recent` (recently played) and use `newest` for the new section
- Register a focus zone for the new row with appropriate vertical zone transitions

### P4.10 — Shrink Play Button on Now Playing Screen
**Problem:** The play/pause button on the Now Playing screen is oversized (68px white circle).
**Fix:**
- Reduce from 68px to 52px
- Adjust the inner icon SVG proportionally
- Keep it as the largest button in the transport controls — prev/next remain smaller
- Ensure the focus ring scales correctly with the smaller button

### P4.11 — Redesign Genre Cards
**Problem:** The random hash-based gradient colours on genre cards look messy and inconsistent.
**Fix:** Replace with a refined, consistent design:
- **Background:** `--bg-card` (#1a1a22) — same dark card as everywhere else
- **Left border:** 3px solid coloured accent from a **curated palette of 8 muted colours** that cycle:
  ```
  #6366f1  (indigo)
  #8b5cf6  (violet)
  #e44d8a  (accent pink)
  #ef4444  (red)
  #f59e0b  (amber)
  #10b981  (emerald)
  #06b6d4  (cyan)
  #3b82f6  (blue)
  ```
  Assign by index: `palette[index % 8]`
- **Border radius:** 12px with `border-left: 3px solid {colour}`
  - Note: Since border-radius with single-side borders looks odd, use `border-radius: 0` and apply `border-left` only. Or use the full border approach: `border: 1px solid var(--border)` with `border-left: 3px solid {colour}`.
- **Text:** Genre name in `--text-primary` (16px, weight 600), album/song counts in `--text-secondary` (13px)
- **Padding:** 20px 24px
- **Focus state:** Standard focus ring (2px accent outline, 4px offset)
- This gives a clean, Spotify-like list/grid feel instead of the rainbow gradient chaos
- Apply the same styling to Quick Access cards on the Search empty state

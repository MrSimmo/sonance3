# P11 — Sonance v1.4 New Features

## Overview
Four new features: gapless playback, star/unstar (favourites), Samsung remote media key registration, and artist detail page with biography.

## Tasks

### P11.1 — Register Samsung Remote Media Keys
**Problem:** Pressing Play/Pause on the Samsung remote shows a Samsung system overlay instead of controlling Sonance. The app needs to register for media key events so the system passes them through.
**Fix:**
- In `js/app.js` init (after login, when the app shell loads), register media keys with the Tizen input device API:
  ```javascript
  if (typeof tizen !== 'undefined' && tizen.tvinputdevice) {
      try {
          tizen.tvinputdevice.registerKey('MediaPlayPause');
          tizen.tvinputdevice.registerKey('MediaPlay');
          tizen.tvinputdevice.registerKey('MediaPause');
          tizen.tvinputdevice.registerKey('MediaStop');
          tizen.tvinputdevice.registerKey('MediaFastForward');
          tizen.tvinputdevice.registerKey('MediaRewind');
          tizen.tvinputdevice.registerKey('MediaTrackPrevious');
          tizen.tvinputdevice.registerKey('MediaTrackNext');
          console.log('[Sonance][App] Registered media keys');
      } catch (e) {
          console.warn('[Sonance][App] Failed to register media keys:', e);
      }
  }
  ```
- The keycodes for these are already handled in the FocusManager (10252 for Play/Pause etc.), but without registration the system intercepts them before they reach the WebView
- Also register colour buttons if not already done:
  ```javascript
  tizen.tvinputdevice.registerKey('ColorF0Red');
  tizen.tvinputdevice.registerKey('ColorF1Green');
  tizen.tvinputdevice.registerKey('ColorF2Yellow');
  tizen.tvinputdevice.registerKey('ColorF3Blue');
  ```
- Wrap in `try/catch` and `typeof` check so it doesn't break in browser
- This must run ONCE during app initialisation, not per-screen
- Also add `<tizen:privilege name="http://tizen.org/privilege/tv.inputdevice"/>` to `config.xml` if not already present

### P11.2 — Star/Unstar (Favourites)
**Subsonic API endpoints:**
- `star.view?id={songId}` or `star.view?albumId={albumId}` — star an item
- `unstar.view?id={songId}` or `unstar.view?albumId={albumId}` — unstar an item
- `getStarred2.view` — returns all starred items (songs, albums, artists)

**Implement in api.js:**
- `star(id, type)` — type is 'song', 'album', or 'artist'. Maps to correct param name (id, albumId, artistId)
- `unstar(id, type)` — same
- `getStarred2()` — returns starred items
- These methods may already be stubbed — flesh them out with actual API calls

**Star button UI — Album Detail screen:**
- Add a star icon next to the album title in the left panel
- Unfocused + not starred: white outline star (☆ SVG, stroke only)
- Unfocused + starred: white filled star (★ SVG, fill white)
- Focused + not starred: pink outline star
- Focused + starred: pink filled star
- Pressing Enter toggles star state → calls star/unstar API → shows toast "Added to favourites" / "Removed from favourites"
- The star is a focusable element in the album detail left panel focus zone

**Star button UI — Album Detail tracklist (per-song):**
- Add a small star icon to each track row (right side, before the duration)
- Same visual states as above but smaller (16px icon)
- Pressing Enter on a focused track row does NOT toggle the star — it plays the track
- Instead, use a keyboard shortcut: **Green button (404 / G)** to toggle star on the focused track
- Update the colour button hint bar: "G ★ Star   Y Add to queue   B Play next"

**Star button UI — Now Playing screen:**
- Add a star icon next to the track title (or below the artist text)
- Same visual states
- Focusable in the NP controls zone (add it as the first or last item in the transport controls row)
- Enter toggles star state

**Starred state tracking:**
- On app load (after login), fetch `getStarred2()` and build an in-memory Set of starred IDs
- When rendering any track or album, check if its ID is in the starred set
- When starring/unstarring, update the set immediately (optimistic) and call the API
- If the API call fails, revert the set and show an error toast

**Cache invalidation:**
- When a star/unstar call succeeds, update the in-memory set
- Don't refetch `getStarred2()` every time — the local set is the source of truth during the session

### P11.3 — Gapless Playback (Near-Gapless)
**Goal:** Minimise the gap between tracks to <100ms. True zero-gap is not achievable with AVPlay's lifecycle, but near-gapless is.

**Approach — Pre-prepare next track:**

**AVPlay backend (Tizen):**
Tizen's AVPlay only supports one active instance. However, we can minimise the gap by:
1. When `oncurrentplaytime` reports the track is within 5 seconds of the end, determine the next track URL
2. Pre-fetch the next track's stream URL (just construct it — no actual HTTP request needed since it's a URL, not a pre-download)
3. When `onstreamcompleted` fires:
   - Immediately call `webapis.avplay.stop()` + `webapis.avplay.close()`
   - Then `webapis.avplay.open(nextUrl)` + `webapis.avplay.setDisplayRect(0,0,1,1)` + `webapis.avplay.prepareAsync(successCb, errorCb)`
   - In successCb: `webapis.avplay.play()`
4. The gap is the time it takes for `prepareAsync` to complete (~50-200ms depending on network/buffering)

This is an improvement over the current approach which does all of this sequentially in the `onstreamcompleted` handler. The key optimisation is having the next URL ready to go.

**Future improvement (not for this patch):** Investigate if Tizen 5.0's AVPlay supports `setStreamingProperty` with pre-buffering hints, or if we can use a background audio element for pre-loading.

**HTML5 Audio backend (browser):**
Use two `<audio>` elements and swap between them:
1. `audioA` and `audioB` — both in the DOM
2. While `audioA` plays, when it's 5 seconds from the end, set `audioB.src` to the next track URL and call `audioB.load()` (preload)
3. When `audioA` fires `ended`, immediately `audioB.play()` and swap the active reference
4. Now `audioA` is the "preloader" for the next-next track
5. This gives near-zero gap in the browser

**Implementation in player.js:**
- Add `_prepareNextTrack()` method that runs when currentTime > duration - 5
- Add `_nextTrackUrl` property that's pre-computed
- Modify the track-ended handler to use the pre-prepared URL/element
- For HTML5: create two audio elements `#sonance-audio-a` and `#sonance-audio-b` in index.html
- Add a `_activeAudio` pointer that swaps between A and B

### P11.4 — Artist Detail Page
**New screen: `screens/artist.js`**

- `getArtist(id)` — returns artist name + list of albums
- `getArtistInfo2(id)` — returns biography (text), smallImageUrl, mediumImageUrl, largeImageUrl, similarArtist[]

**Layout:**

│              │                                          │

**Left panel (fixed, 220px):**
- Artist photo (200px circle) from `getArtistInfo2.largeImageUrl` or fallback placeholder
- Artist name (24px, weight 700)
- Album count (14px, `--text-secondary`)
- "Play All" button — queues all tracks from all albums and plays
- "Shuffle All" button — same but shuffled
- Uses the split-pane pattern (fixed left, scrollable right) from album detail

**Right panel (scrollable):**
- **Albums section:** horizontal grid or vertical list of albums
  - Each album: cover art (80px) + title + year, displayed as a row
  - Clicking an album navigates to Album Detail
  - Focus zone: `artist-albums`
- **Biography section:** (if available from API)
  - "BIOGRAPHY" label (14px, uppercase, muted)
  - Biography text (14px, `--text-secondary`, max ~6 lines with "Show more" if longer)
  - The biography comes from Navidrome's server which fetches it from Last.fm — no direct internet access from the TV needed
  - If no biography available, hide this section
- **Similar Artists section:** (if available)
  - "SIMILAR ARTISTS" label
  - Horizontal row of circular artist avatars (80px) + name below
  - Clicking navigates to that artist's detail page
  - Focus zone: `artist-similar`

**Navigation to Artist Detail:**
- From Library → Artists tab: clicking an artist card navigates to artist detail
- From Search results: clicking an artist result navigates to artist detail
- From Album Detail: clicking the artist name navigates to artist detail
- Register the `artist` screen in the router

**Add to sidebar nav:**
- No — Artist Detail is a sub-page (like Album Detail), not a top-level nav item. It uses the Back button to return.

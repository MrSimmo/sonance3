# P8 — Sonance v1.2.3 Viewport Scaling & TV Spacing Fixes

## Overview
Multiple elements look correct at 1920×1080 in a desktop browser but are oversized, cramped, or overlapping on the Samsung Q90R TV. The root cause is likely a viewport scaling mismatch between the desktop browser and the Tizen 5.0 WebView.

## Root Cause Investigation

The Tizen 5.0 WebView on the Q90R may not respect `<meta name="viewport" content="width=1920">` the same way a desktop browser does. The TV's physical resolution is 3840×2160 (4K), and the WebView may be:
1. Rendering at 1920×1080 but with a device-pixel-ratio of 2 (meaning CSS pixels map 1:1 but images/borders are sharper)
2. Rendering at the native 3840×2160 with the viewport meta tag scaling CSS pixels up — this would explain why everything appears larger
3. Ignoring the viewport tag entirely and rendering at some other resolution

## Tasks

### P8.0 — Viewport Debugging (Do This First)
Add a temporary debug overlay to the app that shows the actual rendering dimensions. This will tell us exactly what's happening on the TV.

In `js/app.js` (or at the end of the init function), add a debug info line that's visible on screen:

```javascript
// Temporary debug — remove after confirming viewport
var debugDiv = document.createElement('div');
debugDiv.style.cssText = 'position:fixed;bottom:0;right:0;background:rgba(0,0,0,0.8);color:#0f0;font-size:12px;padding:4px 8px;z-index:99999;font-family:monospace;';
debugDiv.textContent = window.innerWidth + 'x' + window.innerHeight + ' dpr:' + window.devicePixelRatio + ' screen:' + screen.width + 'x' + screen.height;
document.body.appendChild(debugDiv);
```

Log the output to PROGRESS.md. This tells us:
- `window.innerWidth × innerHeight` = the CSS viewport size the WebView is using
- `devicePixelRatio` = the scaling factor
- `screen.width × screen.height` = the physical screen resolution

Based on the screenshots (things are ~1.5-2x too large), the WebView is likely rendering at 1920×1080 CSS pixels but the effective layout is different due to Tizen's own scaling. 

**If the viewport IS 1920×1080:** the issue is CSS-only (padding/sizing too aggressive). Proceed with the fixes below.
**If the viewport is larger (e.g. 3840×2160):** we need to change the viewport meta tag to match and scale all CSS values accordingly.

### P8.1 — Defensive Sizing: Use Viewport-Relative Units Where Possible
Rather than guessing the exact TV resolution, make the layout more robust by using relative units for key measurements:

- Album art in Library grid: instead of fixed px, use the grid's natural sizing. The grid columns should divide the available width evenly, and album art should be `width: 100%` within each column. This ensures consistent sizing regardless of viewport.
- Ensure ALL grid items use the `padding-bottom: 100%` aspect ratio trick from P7 — no fixed pixel heights on art containers.
- Home screen album cards in horizontal rows: use a fixed width that works at both 1920 and potentially scaled resolutions. Use `calc()` if needed: e.g. `width: calc((100vw - 220px - 48px * 2) / 7)` for 7 items with sidebar and padding accounted for.

### P8.2 — Search Screen: Robust Keyboard/Results Layout
**Problem:** Keyboard and Quick Access panels look fine in browser but are crammed together on TV with broken padding.
**Fix:**
- Use `flex` layout with explicit `gap: 40px` between keyboard and results
- Keyboard panel: `width: 35%` (instead of fixed 480px) with `min-width: 350px; max-width: 500px`
- Results panel: `flex: 1`
- Keyboard keys: use percentage-based or `fr` grid sizing instead of fixed px padding
- Add `padding: 0 48px` to the search screen's outer container (matching other screens)
- Ensure the keyboard grid doesn't overflow its container

### P8.3 — Artists Page: Fix Highlight Size and Truncation
**Problem:** Artist highlight box is massive and gets clipped.
**Fix:**
- Artist cards should have a FIXED maximum width. In the grid, set `max-width` on each card.
- The focus highlight (box-shadow) should be on the card element, not on a wrapper that includes excess whitespace
- Reduce artist avatar size slightly: from 130px to 100px
- Reduce the grid gap and ensure `padding: 8px` on the grid container for outline room
- The long artist name (e.g. "Даниил Трифонов, Mahler Chamber Orchestra...") is causing the card to expand. Fix: `max-width: 100%; overflow: hidden; text-overflow: ellipsis; white-space: nowrap` on the artist name, OR allow 2 lines max with `display: -webkit-line-clamp` (NOT supported on Chromium 63 — use `max-height` with `overflow: hidden` instead)

### P8.4 — Album Grid: More Padding Between Items
**Problem:** Album cards in the Library grid are crammed on the TV.
**Fix:**
- Increase grid `gap` from current value to `gap: 20px 16px` (row gap 20, column gap 16)
- Reduce the number of columns if needed to give more breathing room. Try `repeat(auto-fill, minmax(140px, 1fr))` which will auto-calculate the right number of columns based on available width.
- Ensure album title and artist text below the art has `margin-top: 8px` and uses `font-size: 12px` to save vertical space

### P8.5 — Login Screen: Fix Double Highlight
**Problem:** Active input fields show both the browser's native focus outline AND the app's pink focus highlight, creating a double border.
**Fix:**
- Add to CSS:
  ```css
  .login-card input:focus {
      outline: none !important;
      -webkit-appearance: none;
  }
  ```
- The app's pink highlight (`box-shadow` or custom border) should be the ONLY visible focus indicator
- Also add: `* { -webkit-tap-highlight-color: transparent; }` to suppress any Tizen WebView default highlights
- On Tizen, the WebView may add its own focus styles. Override with:
  ```css
  input:focus, input:active, input:focus-visible {
      outline: none !important;
      box-shadow: 0 0 0 2px var(--accent) !important;
  }
  ```

### P8.6 — Home Screen: Hero Section Padding
**Problem:** The hero banner on the Home screen needs more padding between the cover art and the text/buttons.
**Fix:**
- Increase `gap` in the hero flex layout from current value to `gap: 36px`
- Add `padding: 36px 44px` to the hero content area (match the mockup spec which specified these values)
- Ensure the hero has `overflow: hidden` so nothing bleeds outside the rounded container
- The album title should have `margin-bottom: 8px` above the artist/year text
- Play/Shuffle buttons should have `margin-top: 20px` above them

### P8.7 — Home Screen: Recently Added Highlight Box
**Problem:** The highlight box on Recently Added album cards is oversized and overlaps adjacent cards.
**Fix:**
- Same root cause as the album grid: the focus indicator (outline or box-shadow) extends beyond the card bounds
- Switch to `box-shadow: 0 0 0 1.5px var(--accent)` (doesn't affect layout)
- Remove `transform: scale(1.04)` from home screen album cards — this causes overlap on tightly packed horizontal rows. Use `scale(1.02)` or `scale(1)` (no scale) instead.
- Add `padding: 4px` to the horizontal scroll container to give the box-shadow room
- Ensure each card in the horizontal row has a fixed width (e.g. `162px` as per original mockup) and doesn't resize on focus

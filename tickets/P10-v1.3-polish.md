## Tasks

### P10.1 — Search Keyboard: Full Pink Fill on Focused Key
**Problem:** When a keyboard key is focused, only the text changes. The whole key should fill pink.
**Fix:**
- When a search keyboard key receives focus, set:
  - `background: var(--accent)` (#e44d8a)
  - `color: white`
- When unfocused, revert to:
  - `background: var(--bg-card)` (#1a1a22)
  - `color: var(--text-secondary)`
- Apply the same to SPACE and DEL keys
- This is a simple CSS change on the focused state for keyboard key elements
- Do NOT use outline or border — just background fill

### P10.2 — Back Button: Rounded Rectangle Pink Fill
**Problem:** The back button at the top of sub-pages (Album Detail, Genre songs, etc.) shows as text with a highlight border. Should be a rounded rectangle with pink fill when focused.
**Fix:**
- Back button unfocused: `background: rgba(255,255,255,0.06); color: var(--text-secondary); padding: 8px 20px; border-radius: 10px; border: 1px solid var(--border)`
- Back button focused: `background: var(--accent); color: white; border-color: var(--accent)`
- The button should always be a visible rounded rectangle (not just floating text) — the subtle dark background makes it visible even when unfocused
- Ensure `outline: none` and `transform: none` on focus — no additional highlight artefacts
- Override the generic `.focusable.focused` rule for back buttons specifically

### P10.4 — Album Detail: Split-Pane Layout (Fixed Left, Scrollable Right)
**Problem:** When scrolling the tracklist, the entire page scrolls and the cover art/metadata disappears off the top. The left panel should stay fixed while only the tracklist scrolls.
**Fix:**

Replace the current album detail layout with a split-pane:

```
┌─────────────────────────────────────────────────────────┐
│ [← Back]                                                │
├──────────────┬──────────────────────────────────────────┤
│              │ TRACKLIST                                 │
│  Album Art   │ 65 tracks · 463 min                      │
│  (180px)     │                                          │
│              │ 1  SMD #1                          3:45  │
│  Title       │ 2  Hear Me                         4:12  │
│  Artist      │ 3  SMD #3                          3:30  │
│  Year/Genre  │ 4  Feel Free                       5:01  │
│              │ 5  Samplemania                     4:45  │
│  [▶ Play]    │ 6  Crowd Control                   3:55  │
│  [⤮ Shuffle] │ 7  Feel Good                       4:20  │
│              │ ...scrolls independently...              │
│  (FIXED -    │                                          │
│   does NOT   │                                          │
│   scroll)    │                                          │
├──────────────┴──────────────────────────────────────────┤
│ [Now Playing Bar]                                       │
└─────────────────────────────────────────────────────────┘
```

**Implementation:**

The album detail screen container:
```css
.album-detail {
    display: flex;
    flex-direction: column;
    height: 100%;  /* fill content area */
    overflow: hidden;  /* prevent outer scroll */
}

.album-detail-back {
    flex-shrink: 0;
    padding: 16px 48px 8px;
}

.album-detail-body {
    display: flex;
    flex: 1;
    min-height: 0;  /* critical for flex children to scroll */
    padding: 0 48px;
    overflow: hidden;
}

.album-detail-left {
    width: 200px;
    flex-shrink: 0;
    padding-right: 48px;  /* gap replacement for Chromium 63 */
    overflow: hidden;  /* never scrolls */
}

.album-detail-right {
    flex: 1;
    overflow-y: auto;  /* THIS is the only scrollable area */
    overflow-x: hidden;
    padding-bottom: 20px;
}
```

**Key points:**
- `#content-area` should have `overflow: hidden` when album detail is active (same pattern as Now Playing screen) — the album detail manages its own scrolling
- The `.album-detail-right` (tracklist) is the ONLY element with `overflow-y: auto`
- The `.album-detail-left` has NO scroll — it stays fixed
- `min-height: 0` on the flex body is critical — without it, flex children won't shrink below their content height and scrolling won't work
- The back button is ABOVE the split pane (in its own non-scrolling row)

**Focus and scroll-into-view:**
- When the user presses Down in the tracklist and focus moves to a track below the visible area, the track must scroll into view
- Use `element.scrollIntoView({ block: 'nearest', behavior: 'smooth' })` on the focused track element
- Check if `scrollIntoView` with options works on Chromium 63. If not, use manual scroll:
  ```javascript
  var container = document.querySelector('.album-detail-right');
  var trackEl = focusedElement;
  var trackTop = trackEl.offsetTop;
  var trackBottom = trackTop + trackEl.offsetHeight;
  var viewTop = container.scrollTop;
  var viewBottom = viewTop + container.clientHeight;
  if (trackBottom > viewBottom) {
      container.scrollTop = trackBottom - container.clientHeight + 20;
  } else if (trackTop < viewTop) {
      container.scrollTop = trackTop - 20;
  }
  ```
- The FocusManager should call this scroll logic whenever focus changes within the tracklist zone

**Prevent content area scroll:**
- Add `.album-active` class to `#content-area` that sets `overflow: hidden` when album detail is shown
- Remove it when navigating away

### P10.5 — Pagination for Large Libraries (Prep)
This is prep work for future use — not full implementation, but the foundation:

- In `api.js`, ensure all list-fetching methods accept `offset` and `count` parameters:
  - `getAlbumList2(type, count, offset)` — already should have this
  - `getArtists()` — returns all at once (Subsonic API doesn't paginate artists), so fine
  - `getSongsByGenre(genre, count, offset)` — ensure offset works
  - `search3(query, artistCount, albumCount, songCount)` — has built-in limits

- In the Library Albums tab, if there are more than 50 albums:
  - Initially load 50
  - When the user scrolls to within 5 items of the bottom (i.e. focus reaches item 45+), trigger a fetch for the next 50
  - Append new items to the grid
  - Show a subtle loading indicator at the bottom during fetch
  - Stop fetching when the API returns fewer items than requested (end of list)

- Implement this as a reusable pattern in `utils.js`:
  ```javascript
  function PaginatedLoader(fetchFn, pageSize) {
      this.pageSize = pageSize || 50;
      this.offset = 0;
      this.hasMore = true;
      this.loading = false;
      this.fetchFn = fetchFn;
  }
  PaginatedLoader.prototype.loadNext = function(callback) {
      if (this.loading || !this.hasMore) return;
      this.loading = true;
      var self = this;
      this.fetchFn(this.pageSize, this.offset).then(function(items) {
          self.offset += items.length;
          self.hasMore = items.length >= self.pageSize;
          self.loading = false;
          callback(items, self.hasMore);
      }).catch(function() {
          self.loading = false;
      });
  };
  PaginatedLoader.prototype.reset = function() {
      this.offset = 0;
      this.hasMore = true;
      this.loading = false;
  };
  ```

- Wire this into the Library Albums tab. When focus approaches the last loaded row, call `loader.loadNext()`.
- This keeps DOM size manageable and prevents the TV from struggling with thousands of album cards.

## IMPORTANT Chromium 63 reminders:
- NO `gap` on flex containers — use margin
- Use `grid-gap` not `gap` on grids
- `scrollIntoView({ behavior: 'smooth' })` may not be supported — use manual scroll fallback
- NO `aspect-ratio` CSS — use padding-bottom trick
- NO optional chaining or nullish coalescing
